Getting a group to the same place is a loop of the same three moves: open
Maps, text someone "where are you?", guess their ETA, repeat. It gets worse
as the group grows, and the answers are rarely true ("five minutes away").
Omawe replaces that loop with one shared, glanceable view of everyone's
progress toward a single destination.

## Why we moved off CloudKit

We started with CloudKit as the entire backend, hoping iCloud sync would carry
live trip updates without a custom server. Group user tests proved otherwise:
testers reported stale, inaccurate locations because CloudKit fetches on its own
unpredictable schedule instead of pushing on demand.

## How it's built

A SwiftUI app with an ActivityKit widget extension for the Live Activities,
sharing its types with the app so both sides read the same trip state. Behind
it, the Go backend serves the API and pushes everyone's progress to the rest
of the group over WebSocket.

<CraftList>
  <CraftItem title="Honest under bad signal">When GPS or the network drops, Omawe shows "last seen X ago" instead of a status that looks live but isn't.</CraftItem>
  <CraftItem title="Easy on the battery">Background location and Live Activity updates are tuned so a full trip doesn't drain the phone.</CraftItem>
</CraftList>

## My role

I was the project manager building Omawe at the Apple
Developer Academy from June 2026 to November 2026 through its release on the App
Store. Beyond planning the work and running TestFlight with 26 testers, the
hardest call was cutting scope for v1: we had a share feature planned, but
refining the core trip flow and migrating from CloudKit to Go took priority, so
we moved sharing to the backlog to ship a reliable v1 on time.

## What's next

Version 1 is iOS-only, built around Live Activities. The deferred share
feature, Android support, multi-stop trips, and persistent friend groups are on
the list for later versions.
